# v1.0 开发路线图

## 计划假设

本计划按 2–3 名核心贡献者、每周稳定投入、先建立导出内核再开发完整 Web 流程估算。里程碑按依赖顺序排列，不承诺具体日期；完成条件优先于时间盒。若只有一名兼职维护者，应保持顺序并缩小并行工作，而不是跳过质量门禁。

版本使用 `0.x` 表示协议仍可破坏性调整，`1.0.0-rc.n` 表示功能冻结后的候选版本。

## P0：仓库与工程基线 — v0.0.x

目标：任何贡献者都能在全新环境中安装、检查、构建和理解项目。

交付：

- pnpm monorepo、Nuxt Web、Node 渲染器和核心包边界；
- TypeScript strict、ESLint、Prettier、Vitest 和覆盖率基线；
- CI、依赖更新、安全扫描、Issue/PR 模板和发布工作流；
- Apache-2.0、贡献指南、治理、安全、支持和行为准则；
- 产品边界、架构、路线图和主题协议初稿；
- 第一个可运行编译器、协议校验和 HTML 导出单元测试。

完成条件：`pnpm check` 和 `pnpm build` 在本地与 CI 通过，README 从空环境可复现。

## P1：编译器内核 — v0.1.0

目标：从受控 Markdown 生成稳定、可诊断的语义 HTML。

交付：

- CommonMark、GFM、Frontmatter、脚注和 directive 管线；
- 标题 ID、目录树、图片与图注、Callout、手动分页和代码块规范化；
- `CompiledDocument` v1 内部协议；
- HTML/SVG 清理策略和 URL 规范化；
- 诊断结构：级别、规则、位置、说明和可操作建议；
- 中文、英文、表格、代码、长标题和恶意输入 fixtures；
- AST/HTML 快照和属性测试。

完成条件：所有 P1 fixture 可重复生成；原始脚本、事件属性和危险 URL 无法进入编译结果；核心编译器覆盖率不低于 90%。

## P2：富内容与资源管线 — v0.2.0

目标：安全、可复现地处理真实技术与出版内容。

交付：

- Shiki 静态代码高亮；
- KaTeX 静态公式输出；
- Mermaid 隔离渲染、严格模式和 SVG 二次清理；
- 本地图片解析、格式检测、像素和大小限制；
- 远程资源代理的 SSRF、重定向、超时和缓存策略；
- 资源去重、哈希命名、失败占位和诊断；
- 综合 fixture 与资源攻击回归测试。

完成条件：资源失败不会导致任务失控或静默缺失；禁止访问私网和本地文件；相同输入产生相同资源清单。

## P3：主题 SDK 与预览生成 — v0.3.0

目标：建立可维护、可验证的主题合同。

交付：

- Theme Manifest schema、能力声明和兼容版本；
- 统一语义 class、Design Tokens 和允许用户覆盖的变量；
- `tokens.css`、`content.css`、`screen.css`、`print.css` 分层；
- 主题 fixture 合同测试和作者 CLI；
- 从真实 HTML/PDF 自动生成封面、正文、复杂内容 WebP 样张；
- 视觉 diff 基线、更新审批和跨平台字体基线；
- 主题开发文档和示例主题。

完成条件：新增主题无需修改编译器；预览图由 CI 可复现生成；主题缺失能力或变量时在构建阶段失败。

## P4：PDF 与 HTML 生成服务 — v0.4.0

目标：完成端到端导出纵切面和隔离执行环境。

交付：

- Vivliostyle 分页后端与固定浏览器/字体镜像；
- A4/Letter、方向、边距、封面、目录、页码和页眉页脚；
- 单文件 HTML 的 CSS、字体与资源打包；
- 任务状态机、取消、超时、重试和幂等键；
- 独立工作区、产物保留期和清理；
- 第一页缩略图、页数、大小和校验和；
- 结构化日志、追踪 ID、阶段耗时和标准错误码；
- 容器安全基线与压力/故障测试。

完成条件：smoke fixture 可通过 API 同时生成 PDF 和 HTML；并发失败不会污染其他任务；超限任务返回稳定错误。

## P5：三套首发主题 — v0.5.0

目标：让产品价值首先体现在成品质量，而不是设置数量。

交付：

- Technical Mint：代码、表格、图表和高信息密度；
- Minimal Report：PRD、总结、会议材料和稳定打印；
- Editorial Serif：长文、教程、引用、图文和阅读节奏；
- 每套主题覆盖封面、目录、章节、正文、附录、六级标题、列表、表格、代码、公式、图表、脚注和极端内容；
- 中文标点挤压、孤行寡行、标题避头尾、图片跨页和宽表格策略；
- PDF/HTML 样例与主题详情数据。

完成条件：统一 fixture 的视觉回归通过；P0/P1 排版问题清零；维护者完成打印与屏幕人工验收。

## P6：Web 导出流程 — v0.6.0

目标：完成无实时预览的三步生成体验。

交付：

- 导入：上传、拖放、粘贴、示例文档、摘要和诊断；
- 主题：分类、固定样张、能力、字体、PDF/HTML 支持和选择；
- 配置：文档信息、输出、页面、结构和受控主题变量；
- 生成：阶段状态、取消、错误恢复和重复提交保护；
- 结果：实际缩略图、元数据、下载、另一格式和重新生成；
- IndexedDB 本地草稿恢复和清除；
- 键盘操作、焦点管理、屏幕阅读器和响应式布局；
- 中文/英文界面与错误文案。

完成条件：从导入到下载的 E2E 在 Chromium、Firefox、WebKit 桌面基线通过；无 JavaScript 错误；核心流程达到 WCAG 2.2 AA。

## P7：主题展示与公开测试 — v0.7.0 / v0.8.0

目标：让主题成为产品入口，并用真实文档收敛兼容问题。

交付：

- `/themes`、主题详情、样例 PDF 与在线 HTML；
- 首页导入入口、主题推荐、能力、场景和隐私说明；
- 文档站：格式、扩展语法、限制、隐私与故障排查；
- 匿名错误和性能指标（隐私评审后启用）；
- beta 反馈模板、兼容性矩阵和已知问题；
- 至少 30 份不同结构的许可测试文档；
- 升级、回滚、备份和事故响应演练。

完成条件：连续两周无未解释的 P0/P1 稳定性回归；测试文档通过率达到产品成功标准；反馈可映射到可复现 fixture。

## P8：功能冻结与发布候选 — v0.9.0 / v1.0.0-rc.n

目标：只处理发布阻塞问题，不再加入功能。

清单：

- API、错误码、主题合同和配置 schema 冻结；
- 数据生命周期、隐私政策、服务条款和第三方许可清单完成；
- 威胁模型、依赖审计、CodeQL 和人工安全评审完成；
- 性能、并发、长文档、磁盘耗尽和下游故障压测；
- 无障碍、浏览器、中文/英文、打印和离线 HTML 验收；
- 迁移说明、运维手册、发布说明、演示文档和回滚方案；
- 全新环境与生产等价镜像的可复现构建；
- P0/P1 为 0，P2 有明确处理结论且不影响发布承诺。

每个 RC 至少经过 72 小时观察；任何核心协议或安全策略变化都重新开始观察窗口。

## v1.0.0 发布门禁

只有以下条件全部满足才创建 `v1.0.0` 标签：

1. 产品文档中的所有 v1.0 成功标准达成；
2. `pnpm check`、`pnpm build`、E2E、视觉回归和容器扫描通过；
3. 主分支保护和必需检查已启用；
4. CHANGELOG、升级说明、第三方许可和 SHA256 校验和完整；
5. 安全、隐私、可访问性和运维负责人完成签字；
6. 已验证上一稳定版本的回滚；
7. 发布 Issue 中的所有阻塞项关闭。

## 横向工作流

以下任务不属于单一里程碑，必须持续进行：

- 每个缺陷都先固化为最小 fixture 或自动化测试；
- 每个新能力更新 schema、文档、诊断和威胁模型；
- 每套主题的变更同时验证 PDF、HTML、中文、英文和极端内容；
- 每周依赖更新，每月安全与许可证复核；
- 每个里程碑发布一次 `0.x.0`，紧急修复使用 patch 版本；
- 不以降低测试门槛、关闭扫描或跳过 RC 观察期换取发布日期。

## 风险与缓解

| 风险                       | 早期信号                       | 缓解                                                           |
| -------------------------- | ------------------------------ | -------------------------------------------------------------- |
| 分页引擎对复杂内容不稳定   | fixture 出现随机页数或布局差异 | 固定版本与字体；结构检查 + 视觉 diff；准备有限降级策略         |
| 主题工作变成大量复制 CSS   | 修复必须同步修改多套主题       | 统一语义结构、tokens、合同测试和共享基础层                     |
| Mermaid/远程资源形成攻击面 | 超时、私网请求或异常 SVG       | 隔离渲染、网络策略、允许列表、大小限制和二次清理               |
| Web 功能挤压排版质量       | 编辑器需求不断进入 MVP         | 以产品非目标和里程碑完成条件拒绝范围漂移                       |
| 中文字体与授权阻塞发布     | 开发机正常、容器缺字或不可分发 | 尽早确定可再分发字体、生成字形覆盖测试和许可清单               |
| 视觉回归噪声过高           | 每次 CI 大量无意义 diff        | 固定环境、去随机数据、按组件和页面分层基线                     |
| 维护者负担过重             | Issue 长期无响应、PR 堆积      | 明确标签/SLA、限制同时进行的里程碑、吸纳 reviewer 和模块 owner |
